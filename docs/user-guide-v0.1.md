# 拾序 v0.1 使用与准备说明

当前交付是中文界面、portable 业务/持久化/规则/备份基础及严格发布证据校验器。**真实 Windows 桌面端到端仍 BLOCKED，不能作为已验收的密码管理器或 QQ 自动收集产品使用。** 浏览器演示和注入测试数据不是真实 QQ 接收或主密码解密。Windows 用户已有机器、组件尚未准备；可先准备组件，云端开发不依赖其安装完成。

## 能做什么、哪些还缺少

| 状态 | 当前内容 |
|---|---|
| 已实现并经 portable 测试 | 有类型/权限的命令边界、日历事件事务与来源/历史/撤销/防重放、消息及逐附件状态、白名单/时区/授权设置、确定性文字规则、有限图片/PDF/OOXML算法、注入工作端口的后台协调、保护端口下的SQLite持久化、日历快照/JSON迁移/确认恢复、界面及关闭时清理策略 |
| 未实现/未接通，返回 Unsupported | 真正 VaultEngine、私有引擎会话/本机秘密定时清理、KDBX备份，SystemClipboard及剪贴板历史，QQ wire/真实下载/登录重连，真实隔离parser进程/原生引擎/Windows保护缓存与输入交接；可选模型provider也未选定/未接通 |
| Windows cfg 已写但编译/运行未验收 | Tauri窗口/能力/命令注册、运行时DPAPI目录/SQLite/备份协调、托盘和关闭/退出、owner文件实例排他 |
| 实际钩子尚未实现 | Windows会话锁定/电源事件、自启注册、第二进程通知首进程并聚焦；owner文件锁不等于已有跨进程聚焦 |

部分算法有真实受控本地fixture引擎试验，但生产 host 仍 Unsupported，也没有通过Windows资源隔离。默认bundle关闭，尚无安装包。浏览器仅演示页面；本地数据库和功能必须通过真实Windows IPC/runtime运行才算产品集成。当前生产密码操作不可用，不要输入真实密码以“试一试”。

## 浏览界面和日历

在已有开发环境的仓库根执行 `pnpm install --frozen-lockfile`、`pnpm run dev`，浏览器访问Vite打印的本机地址；`?demo=1` 显示明确标识的演示数据。导航为日历、通知、密码库、设置。周/月/议程和“时间待定”可查看；浏览器未接通原生动作时会明确提示不可用，不应把这种页面当作接收中。

接通合格来源后，启用指定群接收是一次性的知情选择，明确事项自动入历，**不逐条确认**。此为实现基础中的业务行为，当前真实QQ来源尚不存在。未知日期留在时间待定，不猜；已知日期但无钟点显示时间未定，不当作00:00或全天，只有原文明确全天才是全天。精确时间保留时区、原始时间表述和来源定位。

事项详情保留来源消息、必要原文证据、自动/人工历史。可修改标题、时间、地点和状态、手工补录、撤销；人工覆盖不被旧通知/迟到附件覆盖。删除或撤销后保留抑制记录，重放不自动复活。改期/取消找不到可靠目标时保留待关联，不靠到达先后瞎猜。通知中的图片/文件分别显示下载/解析/超限/不支持/部分来源；未取得原件不是“非事项”。连接状态、最后消息和最后入历分别观察，不能以心跳代替真实普通群验收。电脑关机、退出软件期间不承诺收集；重连是否补齐取决于适配器真实能力。

## 密码库规则（目前阻断）

表单业务字段只有**渠道、账号、密码**；同渠道可多个账号，同名条目有内部UUID，不按渠道覆盖。主密码必须真正参与成熟KDBX引擎解密，错误密码不能解锁；当前无生产引擎，所以创建/解锁/读写不是已实现可用功能。安装KeePassXC不会自动使Shixu密码功能可用。

设计及portable策略为密码默认掩码、显示15秒后恢复、复制30秒后只尝试清除**仍是这次写入generation**的内容、不清用户后来复制的数据，5分钟无密码库交互自动锁库；日历/QQ后台不能刷新计时。手动锁定、会话锁定、休眠、退出应销毁会话及迟到结果，关闭主窗口应入托盘并锁库。实际引擎会话、SystemClipboard、计时/历史与Windows钩子还需实现/实测，这些策略测试不证明系统剪贴板已清除。

主密码只锁密码库，日历/QQ应独立运行。没有主密码找回后门；忘记不能重置解密。更改主密码需要旧密码与新密码确认并经引擎重新打开验证；**旧备份仍使用旧主密码**。JS字符串、换页、截图、剪贴板历史和同用户恶意程序也不能承诺彻底清除。真实密码使用必须等G1/V2/V3及Windows发布门槛通过。

## 设置、附件与模型

配置按来源绑定adapter/account/group白名单、时区；历史来源证据不会被当前配置偷偷改写。令牌不是密码条目，也不能进入普通DTO、日志、日历JSON备份。自启默认关闭，当前设置存储不等于Windows登录注册完成。云端模型默认关闭且尚无生产provider；启用文本授权不等于准许上传附件，附件必须另获授权；模型/消息没有密码库接口。模型不是baseline发布的必需组件，未选择时保持关闭即可。

附件上限：图片10MiB/2000万像素/任边10000；PDF/DOCX/XLSX20MiB；每消息5个部件合计50MiB；PDF20页，DOCX/XLSX20万字符，XLSX10表/每表2000行50列/总2万非空单元格；OOXML解压100MiB/5000项/100:1。设计任务单并发、512MiB子进程、单图30秒/单文件120秒、队列100、缓存1GiB；临时下载最多3次重试（1/5/30分钟）。portable限额/队列有测试，实际Windows进程内存/网络/时间隔离未实现。30天正文/非事项原件清理和关联原件保护是设计保留政策，不能理解为当前已接通真实清理；关联原件不应静默逐出。模糊图片、复杂布局/Office和中文OCR存在已记录漏识别，不可静默算成功。

## 备份、迁移和恢复

日历已实现的基础：每天最多一份，保留最近7个每日快照，SQLite与原件清单一致，单独保留恢复前检查点。快照通过DataProtector保护；Windows拟用用户级DPAPI，当前同用户/第二身份及ACL实测未完成。DPAPI快照不承诺跨Windows用户或跨机可恢复；请保留原Windows身份。生产没有接通Windows原件缓存；遇到声明Present但没有可用cache的原件会Unsupported，**不会生成虚假的完整快照**。没有Present原件的日历可走当前基础路径，实际Windows还需验证。

设置中的恢复先提供预览（数量、缺失原件状态），再单独确认；可信预览ID有时效且一次性使用，原件/库变化会拒绝。恢复前保存当前状态；成功恢复保留来源历史、人工覆盖、撤销和抑制，接收/模型/自启关闭，之后由用户明确重新启用。日历JSON导入最大20MiB（发布证据JSON另限1MiB）。导入只预览，不能自动替换或接收。删除事项不代表旧备份已经删除相同数据；备份会保留当时正文/必要证据/撤销记录，按保留策略或用户明确删除备份处理。

主动导出的日历JSON是**明文**。默认不含完整消息正文/二进制原件/任何凭据，但仍有必要事项证据摘录、来源和历史，摘录可能与短原文一样长；选择完整正文时还会含聊天正文。仅在明确导出确认后保存，并检查浏览器下载结果；不要随意发送该文件。JSON迁移可以在目标身份重新保护数据，但不迁移原件，missing状态明确显示not_migrated。备份文件里never_fetched/cleaned等状态不同，不能凭空恢复原件。

密码库加密备份保留最近10份是设计政策；当前KDBX引擎和密码备份Unsupported，**没有可用的10份密码快照功能**。旧密码快照仍需旧主密码，删除条目/改主密码不擦除旧备份中的旧数据。

## 在自己的Windows上准备下一轮验收

先按 [Windows门槛说明](verification/windows-release.md) 准备C++工具、Rust MSVC、Node/pnpm/Git和WebView2；相关官方来源已于2026-10-09复核：[Tauri](https://v2.tauri.app/start/prerequisites/#windows)、[Microsoft WebView2](https://learn.microsoft.com/en-us/microsoft-edge/webview2/concepts/distribution)。`pnpm run tauri build` 当前只尝试本地二进制，bundle关闭，无安装包承诺。

再独立从 [KeePassXC官方页](https://keepassxc.org/download/#windows) 准备可信Windows组件并记录版本、校验/来源/许可。在**引擎实现之后**只用虚构密码做私有会话、UUID/Unicode/换行三字段及KeePassXC GUI双向往返；只安装组件不能关闭G1。

QQ需要自己选择/配置许可合适的适配器、专用测试账号和获准测试群、白名单/时区，在本机登录。**QQ wire实现之后**才可做100条合成消息、各类型附件原件、8小时和P95证据。无需发送任何访问令牌、真实密码或聊天秘密到对话中。

开发还需补齐引擎/会话/KDBX、剪贴板/历史、QQ wire和下载、parser sandbox/Windows cache、会话电源钩子/自启/跨进程聚焦/打包，并修复完整附件质量。真实Windows构建/WebView权限、同/不同身份DPAPI/ACL、文件占用/磁盘满/崩溃恢复/剪贴板/Job Object等测试必须独立验收。精度≥95%/召回≥90%按每类型全部冻结数据报告，含糊猜测0；目前纯文字157/132 gold TP123 FP3 FN9达标，DOCX入历P75% R35.29%、XLSX P57.14% R30.77%、中文OCR每例1/2区域和6/10定位未达标。完整字符/标题/gold分母见Windows门槛说明，不会移除unsupported正例以“通过”。

发布校验器只生成诚实的PASS/FAIL/BLOCKED报告；当前构建即使收到自称全通过的JSON也保持native BLOCKED。安装、程序启动、mock通过和ignored零失败均不等于全产品完成。
