# N4 image/PDF bounded algorithm delivery

Recorded 2026-10-09. **Portable Rust algorithms and controlled real-engine fixtures pass; product native integration and Windows acceptance remain BLOCKED. N4 is a bounded partial delivery, not complete format support.**

## Architecture and boundaries

`attachments/image.rs` implements PNG/JPEG-only detection, compressed byte and pre-decode dimension/pixel limits, bounded Rust decoding, post-decode dimension validation, OCR observation validation, conservative line-region assembly and quality flags. `OcrEngine` is an explicit port, without a default native implementation. `extract_with_engine(bytes, part_id, limits, engine)` is a reusable algorithm intended for the future isolated worker. Pixel dimensions are capped at 10,000 per edge / 20 million pixels; bytes at 10 MiB. Overrides only tighten those caps. Decoder allocation limits use at most 512 MiB; this is not an OS process-memory guarantee.

`attachments/pdf.rs` validates the 20 MiB byte cap and PDF signature before `PdfReader::open`, rejects more than 20 pages before page access, validates every page's raster dimensions, and uses native text first with OCR only for pages without native text. Native whitespace is preserved; glyph ink gaps never fabricate date spacing. Bounding boxes have a top-left origin in pixels at the reader's declared page size (the fixture adapter uses 72 dpi, rounded up). Native glyph observations and OCR words become coherent line regions where their geometry supports assembly. Large horizontal gaps preserve separate table/column regions; overlapping or competing observations remain unjoined with `AmbiguousLayout` and `PartialParse`. No cross-page assembly occurs. Blank failed pages mark retained evidence `PartialSource`. Hard limit/invalid geometry errors discard the part's tentative output.

Both algorithms conservatively cap extracted characters at 200,000 including inserted word spaces. OCR weak confidence (<85), edge clipping, or low ink sharpness marks `UncertainDate`/`PartialSource`; no date is inferred. Ink sharpness is average squared four-neighbor Laplacian over nonwhite pixels (threshold 200). This conservative heuristic fixed a real confident-blur failure in these fixtures; it is not a calibrated universal readability classifier. Neither algorithm emits executable HTML.

The requested path-based `image::extract_image` and `pdf::extract_pdf`, `host::parse_part`, and the normal parser executable remain `Unsupported` (binary exit 78). **Engine invocation lives only in `tests/support/image_pdf_engines.rs`, never in the shipped library or parser.** It checks committed synthetic fixture hashes and installed engine/model hashes. The native adapters use Rust subprocess/FFI APIs; Python is used only to generate fictional fixtures and collect developer evidence, not as an application runtime. No runtime switch authorizes unsandboxed user input.

## Fixtures and measured quality

The deterministic generator writes **20 images and 20 PDFs**, only fictional notices. It takes no external input. Python Pillow 12.3.0, pypdf 6.10.0 and installed Noto Sans CJK fonts are generation dependencies. Two consecutive generation runs produced identical bytes for all 44 fixture-directory files, including manifests and encrypted PDF. Every input filename/hash is explicitly listed; `.gitignore` allows only these reviewed files.

Coverage includes PNG/JPEG, Chinese, multiline/columns/simple tables, grayscale/alpha, blur/crop, blank, corrupt/truncated, over-edge/over-pixel images, native/scanned/mixed PDF pages, encrypted/malformed PDF, 20/21 pages, oversized page, and action/embedded/XFA dictionaries.

Final measured counts after coherent-region assembly:

| Type | Inputs | Complete annotated text regions | Located emitted boxes |
| --- | ---: | ---: | ---: |
| Images | 20 | 29/31 = 93.55% | 39/47 = 82.98% |
| PDF | 20 | 72/73 = 98.63% | 77/81 = 95.06% |

A complete region contains its entire manually specified fictional string after whitespace normalization, using only output boxes fully contained within that region's annotated rectangle on the correct page. A located box is wholly inside at least one annotated text rectangle on its page. Text fragments are not credited outside the annotation; these measures combine recognition/geometry and are not event precision/recall. The PDF denominator excludes **44 annotated regions belonging to correctly rejected 21-page/oversized-page files**; their raw zero-output results remain in the log. Negative/blank files have no text-region denominator. All readable and degraded positive fixtures remain counted, including failures.

**Chinese quality remains below target:** each Chinese image and the Chinese scanned PDF gets only 1/2 complete regions and 6/10 located boxes. Overlapping Chinese word observations remain unjoined and `PartialParse`; no fixture was relabeled negative to improve metrics. Final raw case counts and resource summaries are in [N4-quality.json](N4-quality.json). N6 real event precision/recall and ambiguous-date-guess counts have not been run. These small repeated synthetic examples are not representative product-quality acceptance.

## Verification and remaining gates

- `cargo test -p shixu-native --test image_pdf`: **14 passed**, including behavioral RED→GREEN evidence for table geometry, date-quality flags, mixed pages, page/byte limits, coherent regions, ambiguous layout and inserted-space character budgets.
- `cargo test --workspace`: **171 passed, 0 failed, 3 ignored**. Ignored cases are two real Windows DPAPI/ACL cases and one real Windows parser-isolation gate; they are not acceptance passes.
- `cargo test -p shixu-native --test parser_isolation -- --ignored`: **exit 101**, `parser_has_no_network_or_vault_access` fails explicitly BLOCKED. No Windows restricted token/AppContainer, ACL handoff, Job Object memory/process cap, or real network/vault denial is implemented/exercised.
- `strace -f -e trace=%file,%network ... pdf_actions_never_execute --exact`: exit 0; **0 open/exec calls** to the attacker-referenced synthetic canary path, **0 connect/send calls** in the action/embedded/XFA fixture run. Four canary existence-stat calls belong to the test. Libraries/fonts are expected non-input reads. This tests those fixtures' behavior, **not OS denial or a blanket zero-filesystem-access claim**.
- Separate already-built test runs: 20 image fixtures **6.0808 s**, max child RSS **88,244 KiB**; 20 PDF fixtures **3.7996 s**, **75,568 KiB**. Python `os.wait4` collected wall time and child rusage. RSS is the maximum process measurement, not concurrent aggregate Job Object usage or a worst-case bound. Tesseract fixture calls have a 30-second watchdog; no native Windows 30/120-second or 512 MiB acceptance is implied.

Still open: production native adapters and read-only handle handoff, actual Windows isolation/cache/resource regression, comprehensive quality calibration and Chinese layout/recognition improvement, N6 event metrics, and real QQ original-file acquisition. Product dispatch must remain closed until the corresponding gates pass.
