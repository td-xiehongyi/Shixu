# OneBot 11 text receive transport

`shixu_native::qq::onebot::connected_onebot_receiver` is a production assembly function: pass a trusted `LoopbackEndpoint`, `SourceConfig` (`adapter_type = "onebot11-text"`, decimal account/group IDs, capability `LiveMessages`), independently protected in-memory `SecretBytes`, the same database's `MessageStore`, and a clock. Put the resulting receiver into `WorkerPorts.receiver` for an already configured `Supervisor`. The factory connects and checks the first event's `self_id`; it can block for up to approximately three seconds total (one second each for TCP connect, HTTP upgrade, and first event). Call it outside the UI thread.

The transport connects with `TcpStream::connect_timeout` to a parsed literal loopback socket address. It uses tungstenite **0.30.0** (MIT OR Apache-2.0), HTTP upgrade on **`/event`**, and a sensitive **Authorization: Bearer** header. It never uses hostname lookup, proxy discovery, redirects, token query parameters, environment/argument token inputs, or business/API message sends. Tokens must contain 1–4096 ASCII graphic bytes. `SecretBytes` and the temporary bearer buffer are zeroized on drop; HTTP header and tungstenite handshake buffers contain unavoidable transient library-owned copies which do **not** promise zeroization. They are dropped after handshake. tungstenite traces its raw request and frame bodies; pinned `log` 0.4.34 with `max_level_info` and `release_max_level_info` compiles out DEBUG/TRACE calls for the entire final binary, including its dependencies (a deliberate loss of debug diagnostics, retaining INFO/WARN/ERROR). A real handshake with a TRACE-enabled capture logger verifies no bearer or private body reaches logging. Errors exposed to the app are fixed `AppError` values, never request/response/header dumps.

Nonblocking handshake and polling enforce absolute deadlines **inside** the stream `Read`, `Write` and `flush` calls, with a 2 ms wait on `WouldBlock`. `DeadlineTcpStream` returns `WouldBlock` at expiration even if TCP remains continuously readable, interrupting tungstenite's internal loop over nonfinal empty continuation frames. Each underlying read/write is capped at 8 KiB; the library can still finish parsing finite bytes already buffered and Rust is not a real-time scheduler, so approximately 100 ms is a cooperative polling bound rather than CPU preemption. The message/frame caps separately bound payload processing. Partial frame state stays in tungstenite for the next poll. Disconnect queues only a protocol close, attempts a nonblocking flush and shuts down TCP without waiting for peer acknowledgment. Frame and assembled message bounds are 1 MiB; tungstenite's handshake `AttackCheck` additionally rejects cumulative incoming HTTP data above 65,536 bytes and more than 512 successful reads (plus its small-packet checks). HTTP 401/403 maps to `AuthFailed`; malformed JSON/protocol/oversized handshake, overflow and oversized frames are rejected with fixed errors.

Every event checks `self_id` against the configured account. Group whitelist filtering precedes message content interpretation and persistence. Only group messages containing an array of exclusively `text` segments become envelopes; all text segments are concatenated without trimming or newline conversion. Signed int32 `message_id` is mapped to its decimal string; existing source/account/group identity mapping and durable cursor acknowledgment supply idempotency. Event seconds use checked multiplication to milliseconds. CQ strings and mixed/nontext arrays return `Unsupported`, never a partial envelope. After an unsupported event is fully consumed, the adapter exposes that error and can receive the next event; transport/protocol and identity failures stop the adapter until explicit reconnection. Private messages, notices and requests are ignored; heartbeat/lifecycle only establish identity, never ordinary-group acceptance.

Only `LiveMessages` is declared. Backfill, attachments, replies, revocations and edits are unsupported. No automatic reconnect or historical completeness is claimed. The Windows Tauri runtime now installs a thread-owned managed receiver in `WorkerPorts.receiver`. Settings supplies a write-only protected connection entry point and explicit connect/disconnect actions; see [safe connection flow](qq-connection-ui.md). This implementation adds no plaintext token persistence. Windows QQ/NapCat installation/login, exact local component and QQ versions, ordinary-group no-mention delivery, sleep/reconnect and attachment evidence remain the separate **G2** requirement. Local synthetic socket tests do not pass G2, D7 or the twelve release gates.

Protocol sources (accessed 2026-10-10): [forward WebSocket](https://raw.githubusercontent.com/botuniverse/onebot-11/master/communication/ws.md), [authorization](https://raw.githubusercontent.com/botuniverse/onebot-11/master/communication/authorization.md), [message event](https://raw.githubusercontent.com/botuniverse/onebot-11/master/event/message.md). Library: [tungstenite 0.30.0](https://docs.rs/tungstenite/0.30.0/tungstenite/), approved crates.io dependency pinned in Cargo.toml/Cargo.lock; handshake limits verified in downloaded version's `src/handshake/machine.rs`.

Run `cargo test -p shixu-native --test onebot_text --test qq_adapter --locked --offline` and `cargo test -p shixu-core --test background_runtime --locked --offline` with the repository toolchain. Tests use only synthetic local tokens and loopback servers, and a test-only protector, never QQ or real credentials. The socket-to-calendar test invokes the production factory, runs `BackgroundWorkers`, proves a later marker cursor passes the duplicated notification in order, checks allowed-only storage and one calendar entry, then checks bounded worker stop. Additional socket cases cover fragmented messages spanning a poll deadline, ping/pong, malformed/oversized inputs, first-event identity, forbidden groups, unsupported-event continuation, HTTP auth rejection idle handshake timeout, and continuously supplied nonfinal empty continuation frames during first-event authentication, polling and worker stop. The latter cases failed before the stream deadline repair and pass afterward.
