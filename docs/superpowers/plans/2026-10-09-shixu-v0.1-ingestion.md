# Shixu v0.1 通知采集与解析 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 将指定 QQ 群文本与获准格式附件转为可追溯、可重放的事项候选，任何缺失或失败均可见。

**Architecture:** 白名单入口先持久化消息，再把文本和附件交给限额隔离解析器；提取只产生候选，D1 的事件事务服务决定入历。Windows 数据保护和真实 QQ 适配可替换，云端用合成 transport 与 test-only protector，不混淆真实验证。

**Tech Stack:** Rust、SQLite、用户独立配置的 QQ 组件；OCR/PDF/XML/工作簿候选经 N3 选择验证，具体引擎版本必须固定并记录。

**Spec:** [已批准设计](../specs/2026-10-09-shixu-v0.1-design.md)第 6–11、13 节；共享类型和批准记录见[总览](2026-10-09-shixu-v0.1-implementation.md)。

## Global Constraints

继承总览全部限制，尤其 10/20/50 MiB、5 部件、20页、20万字符、10表/2000行/50列/2万非空格、100MiB解压/5000条目/100:1、512MiB/30或120秒、1并发/100任务/1GiB。所有数据不可信，不执行宏/公式/附件，不读取密码库；不自动上传图片或附件。真实 QQ 未验收时只标注模拟，不阻塞本地领域测试。

## Review Focus

继承总览五项风险；本篇负责账号/游标命名空间、旧附件迟到、虚假的连接成功，通过 N1/N2/N6 的具名测试覆盖。

## 文件职责与依赖

N1 建持久消息与保护端口；N2 建 QQ 连接与重连；N3 建下载、限额和隔离宿主；N4 建图片/PDF；N5 建 DOCX/XLSX；N6 建本地时间与事项提取；N7 建可选模型授权。N6 的纯文字部分仅依赖 N1/F0，可在 Windows G2 阻塞时推进；N7 不要求真实云端账号即可测授权边界。

实现文件按 `notifications/`、`attachments/`、`protection/` 分组；每个解析器独立文件。禁止在一个组件中混合下载、执行第三方引擎、事件数据库写入和 UI 渲染。
