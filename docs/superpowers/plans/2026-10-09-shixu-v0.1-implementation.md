# Shixu v0.1 总览与可行性门槛 Implementation Plan

2026-10-10 剪贴板需求修订：复制账号/密码后不因计时、锁库或退出自动清除；内容保留至用户覆盖或手动清除，可能留有密码。15 秒掩码、5 分钟闲置锁库、会话撤销和瞬时秘密内存清零保持要求；原生复制、历史/云同步排除及权限隔离仍须真实验收。
> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 将已批准的设计分解为可独立验证的密码库、通知解析与日历桌面模块，先证明高风险集成可行。

**Architecture:** Rust 核心负责领域规则与事务，原生适配层负责 Windows、密码引擎和 QQ；React 界面通过受限 Tauri IPC 使用这些能力。密码引擎与附件解析各自隔离，日历和采集不依赖密码库解锁。当前仓库没有应用，本计划中的所有目标代码、测试和执行命令均为未来工作。

**Tech Stack:** Tauri、React、TypeScript、Rust、SQLite、KDBX4/KeePassXC、本地 OCR 和分类型附件解析；依赖版本在所属可行性任务核验并固定，不在本轮安装。

**Spec:** [2026-10-09-shixu-v0.1-design.md](../specs/2026-10-09-shixu-v0.1-design.md)，本计划基于提交 `7c22f28` 的设计快照。

## Global Constraints

- 本轮仅编写并提交文档；所有复选框保持未执行。没有应用初始化、依赖安装、登录 QQ、真实凭据操作、推送或部署授权。
- 用户已在本轮批准完整修订设计，包括格式范围及独立配置第三方 QQ 接入方向。原设计文件按要求保持不变，其“待确认”属于审阅前快照；最新批准状态以本段为准，不重复请求该产品方向的批准。
- 设计批准不等于环境安装、账号登录或真实数据使用已经发生；进入执行需先审阅本计划并选择执行方式。额外管理员权限、外部组件安装与账号登录在实际需要时由用户完成或另行明确授权。
- 密码条目的业务字段只有**渠道、账号、密码**，同一渠道允许多个账号；主密码真正参与解密。禁止真实秘密用于测试，禁止密码/令牌出现在参数、环境变量、日志、遥测或临时明文文件。
- 主密码只锁密码库；日历、QQ 接收、附件解析独立运行。云端模型默认关闭，消息与模型无密码库接口；附件不因文字授权自动获准上传。
- 显示密码默认 15 秒恢复掩码；复制后不自动清除，保留至用户覆盖或手动清除；无密码库交互 5 分钟自动锁库，后台消息不刷新解锁计时。
- 日期不明确不猜测；自动入历不逐条确认；保留来源、人工修改、撤销与防重放抑制记录。关机收集、通用 Agent、宏/公式执行与外部日历同步不在范围。
- 单张图片 ≤ 10 MiB、解码后 ≤ 2000 万像素且任一边 ≤ 10000 像素；PDF/DOCX/XLSX 单文件 ≤ 20 MiB。每条消息最多 5 个图片/文件部件、合计 ≤ 50 MiB。
- PDF ≤ 20 页；DOCX/XLSX 每文件最多 20 万提取字符；XLSX 最多 10 个工作表、每表 2000 行/50 列且全文件最多 2 万个非空单元格。
- DOCX/XLSX 累计解压量 ≤ 100 MiB、条目数 ≤ 5000、压缩比 ≤ 100:1；默认 1 个解析任务、512 MiB 子进程内存、单图 30 秒/单文件 120 秒、待处理任务最多 100 个、附件缓存 1 GiB。
- 临时下载故障最多重试 3 次，间隔 1、5、30 分钟；非事项正文和原件 30 天清理，关联原件不静默逐出，抑制记录保留到来源重置。
- 密码加密快照保留最近 10 份；日历每日最多一份、最近 7 份，SQLite 与原件清单一致。DPAPI 快照不能承诺跨机；日历明文 JSON 仅用户主动导出。
- QQ 基线 100 条已知测试消息、8 小时后台运行；在线接收到持久化 P95 ≤ 5 秒、规则入历 P95 ≤ 10 秒。纯文字质量集至少 120 条、各附件类型至少 20 例，精度≥95%、召回≥90%，含糊日期猜测为 0；各类型单独报告。
- 固定版本、保留来源及许可记录，禁止把 keepass-rs 实验性写入或未验证 KdbxWeb/Argon2 当作真实密码后端；不打包再分发 NapCat 或假设已有许可。

## 3. 共享类型、测试约定与命令语义

F0 定义下列 Rust 类型；同名 TypeScript DTO 在 D2 映射并使用样例验证一致。数据字段采用设计第 6 节的 snake_case；不以随意 JSON 替代接口。ID 为不透明 UUID 字符串 newtype，`Revision=u64`、`UtcMillis=i64`、`AppResult<T>=Result<T,AppError>`。

| 类型 / 所属文件 | 决定的结构与含义 |
| --- | --- |
| `AppError` / error | `Locked, AuthFailed, Unsupported, Conflict, StorageFull, Disconnected, ParseFailed, InvalidInput`；IPC 映射大写错误码，无敏感文本 |
| `SecretBytes`、`SessionId`、`VaultRecord`、`VaultSummary` / vault | SecretBytes 禁止 Debug/日志序列化并尽力零化；record 含三业务值、ID/修订/时间，summary 无密码；会话 ID 不能当作前端通用访问令牌 |
| `VaultMutation` / vault | `Create{channel,account,password}, Update{id,expected_revision,channel,account,password}, Delete{id,expected_revision}` |
| `LockReason`、`VaultStatus` / vault | 手动/超时/会话锁定/休眠/退出；状态未创建/锁定/解锁中/解锁，错误保持锁定 |
| `SourceConfig`、`SourceId`、`MessageKey`、`MessageEnvelope` / notification | 设计字段 + `parts:Vec<MessagePart>`；来源绑定 adapter/account/group 命名空间，令牌不在 DTO |
| `MessagePart`、`AttachmentRef`、`EvidenceBlock` / notification | 原始部件引用、下载状态、内容摘要、页/区域/单元格定位；本机秘密下载 URL 不作长期字段 |
| `Method`、`QualityFlag` / notification | Method为NativeText/Ocr/Cell；QualityFlag为UncertainDate/AmbiguousLayout/FormulaDerived/PartialSource，区分字符提取与时间解释 |
| `PartStatus`、`PartResult`、`ParserLimits` / notification | 状态采用设计 8.3；PartResult 含 part_id/status/blocks/reason_code，不含任意异常堆栈；限制值复制全局约束 |
| `Candidate`、`ExtractBatch` / notification | Candidate 含 `candidate_key,action(Create/Reschedule/Cancel),title,kind,time,location,evidence,target_message_key`；ExtractBatch 含 message_key/message_revision/source_order/candidates/part_results/extractor_version |
| `TimeValue`、`Precision` / calendar | Precision 为 UnknownDate/DateOnly/Exact/ExplicitAllDay；TimeValue含precision/local_date/start_at/end_at/timezone/raw_time_text；缺失值为 Option，不用 00:00 代替 |
| `CalendarEvent`、`EventStatus`、`ChangeId`、`ApplySummary` / calendar | 事件采用设计字段，EventStatus为Active/Cancelled/Removed；summary 含 created/updated/cancelled/pending/conflicts 计数与 change_ids，不返回整库 |
| `EventPatch`、`EventQuery`、`UndoRequest` / calendar | 用户只改 title/time/location/status；写入附 expected_revision；UndoRequest 含 change_id/expected_revision |
| `BackupManifest`、`RestorePreview` / backup | schema_version/时间/实体数量/blob 摘要与缺失状态；不含凭据；恢复预览需要新的确认动作 |

所有任务使用绝对工作根或在仓库根运行。未来命令分为：`cargo test -p shixu-core --test NAME`（云端逻辑）、`cargo test -p shixu-native --test NAME`（平台适配器）、`pnpm exec vitest run PATH`（UI/契约）、`pwsh -NoProfile -File scripts/verify-*.ps1`（Windows 门槛）。F0/D2 创建必要配置后这些命令才存在，本轮不执行它们。原生真实集成用 `-- --ignored` 显式选择，缺 OS/组件/登录应返回阻碍，不能跳过后以 0 失败作为成功证据。

每个实现任务按 5 步推进：写具名测试与明确断言 → 运行见到预期功能失败 → 最小实现 → 同命令通过并满足该任务验收 → 只提交该任务文件。测试代码块为关键断言片段，局部变量在具名测试中按描述构造，不是待运行的完整实现。缺编译器/依赖/测试配置不算有效的“红”；先完成已授权的基础配置。每次提交执行 `git diff --cached --check`，用 `git add -- <该任务列出的实际文件>`，不使用全库暂存。
