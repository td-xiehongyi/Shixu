# Shixu v0.1 安全密码库 Implementation Plan

2026-10-10 剪贴板需求修订：复制账号/密码后不因计时、锁库或退出自动清除；内容保留至用户覆盖或手动清除，可能留有密码。15 秒掩码、5 分钟闲置锁库、会话撤销和瞬时秘密内存清零保持要求；原生复制、历史/云同步排除及权限隔离仍须真实验收。
> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 提供真正由主密码解密、锁定后拒绝访问、可恢复的独立三字段密码服务。

**Architecture:** 核心策略只依赖 VaultEngine 端口，假引擎用于云端失败路径测试，真实引擎在独立进程内运行。Windows 文件提交、会话与剪贴板由原生层承担；QQ、模型、日历均不持有密码服务对象。

**Tech Stack:** Rust、标准 KDBX4、KdbxWeb 2.1.1 + hash-wasm 4.12.0 + Node 26.11.1 独立进程；不新增自行实现的密码算法。

**Spec:** [已批准设计](../specs/2026-10-09-shixu-v0.1-design.md)第 3、5、6、12 节；批准状态和共享契约见[总览](2026-10-09-shixu-v0.1-implementation.md)。

## Global Constraints

继承总览全部全局约束、类型与提交规则。仅使用合成密码；保持渠道、账号、密码三字段；15秒显示/复制不自动清除/5分钟锁定；保留10份加密快照。G1 不通过时，V1 可独立完成，但 V2/V3 真实引擎验收保持阻塞；不能为赶进度切换实验性写入库。

## Task V1：密码服务契约、会话与最小条目操作

**依赖/环境：** F0；云端，使用显式 FakeVaultEngine，不声称验证加密。UI 在 D3。

**Files:** Create `crates/shixu-core/src/vault/{mod.rs,ports.rs,session.rs,service.rs}`, `crates/shixu-core/tests/vault_policy.rs`, `crates/shixu-core/tests/support/fake_vault.rs`；Modify core `src/lib.rs`、`tests/support/mod.rs`。

**Interfaces:** 在 ports.rs 定义 `VaultEngine` trait：`create(master:SecretBytes)->AppResult<()>`、`open(master:SecretBytes)->AppResult<()>`、`close()->AppResult<()>`、`list()->AppResult<Vec<VaultSummary>>`、`apply(m:VaultMutation)->AppResult<VaultSummary>`（Delete 返回删除前 summary，调用端只使用成功状态）、`read_secret(id:&str)->AppResult<SecretBytes>`、`change_master(current:SecretBytes,next:SecretBytes)->AppResult<()>`。实现时方法接收 `&mut self`，敏感参数消费所有权。V2 实现端口，V3 加入持久提交。

`VaultService<E:VaultEngine>` 在 service.rs 提供 `new(engine:E)->Self`、`create/unlock(master:SecretBytes,now:UtcMillis)->AppResult<SessionId>`、`lock(reason:LockReason)->AppResult<()>`、`tick(now:UtcMillis)->AppResult<()>`、`status()->VaultStatus`、`list(session:&SessionId,now:UtcMillis)->AppResult<Vec<VaultSummary>>`、`apply(session:&SessionId,m:VaultMutation,now:UtcMillis)->AppResult<VaultSummary>`、`reveal(session:&SessionId,id:&str,now:UtcMillis)->AppResult<SecretBytes>`、`change_master(session:&SessionId,current:SecretBytes,next:SecretBytes)->AppResult<()>`。列表/显式密码库交互可刷新活动时间，QQ/日历没有刷新接口；D3 的显示时限与剪贴板逻辑另验。

- [ ] **Step 1 — 测试：** 写 `locked_rejects_every_secret_operation`、`duplicate_channel_account_uses_distinct_ids`、`password_is_not_trimmed`、`background_does_not_extend_timeout`、`late_reply_after_lock_is_discarded`；覆盖创建后重锁、错误密码、空字段、旧 session、新解锁会话、修订冲突与查询不含密码。关键断言：`assert_eq!(service.list(&old_session, now), Err(AppError::Locked)); assert_eq!(service.status(), VaultStatus::Locked);`；在时钟推进到 299999/300000 毫秒两侧验证边界，不用真实 sleep。
- [ ] **Step 2 — 红：** `cargo test -p shixu-core --test vault_policy`；预期至少授权/超时用例失败，不接受所有测试被忽略。
- [ ] **Step 3 — 实现：** session.rs 按状态机管理不可复用的会话 ID；service.rs 校验字段与预期修订，将解密交给引擎；SecretBytes 不 Debug，不保存独立“已验证主密码”标记。锁定先使会话无效、取消请求，再关闭引擎；关闭异常仍对外锁定，错误仅输出固定码。
- [ ] **Step 4 — 绿/验收：** 同命令全部通过；明确拒绝 locked 下 list/apply/reveal/change_master；延迟返回无法把旧秘密送到新会话。对 Fake 引擎测试结果标为策略测试，不能写“密码安全通过”。
- [ ] **Step 5 — 提交：** 仅 V1 文件；`feat: add isolated vault session policy`。

- [ ] **Step 1 — 测试：** `master_really_decrypts_kdbx`、`all_business_fields_use_private_pipe`、`protocol_injection_is_data`、`engine_exit_invalidates_session`、`started_is_not_verified`、`roundtrip_preserves_uuid_and_bytes`。恶意输入含换行、引号、管道符和同名条目；断言 `assert_eq!(wrong_master_result, Err(AppError::AuthFailed)); assert_eq!(leak_scan.matches, 0); assert_eq!(reopened.password.expose(), original.expose());`。金丝雀检索覆盖 argv、受控日志和工作目录，不声称证明系统换页无残留。

## Task V3：原子保存、改主密码、备份与恢复

**依赖/环境：** V2；故障调度可云端用假文件系统验证，Windows 原生替换/占用文件/引擎重开必须实测。

**Files:** Create `crates/shixu-native/src/vault/{commit.rs,backup.rs}`, `crates/shixu-native/tests/vault_recovery.rs`；Modify native `vault/{mod.rs,engine.rs}`、core `vault/ports.rs`；Create `tests/fixtures/vault/manifest.json`（仅合成库说明，KDBX 测试文件运行时生成）。

**Interfaces:** commit.rs 定义 `VaultCommitter::begin(expected_digest:&str)->AppResult<PathBuf>` 返回加密工作副本；`commit(work:&Path,expected_digest:&str)->AppResult<String>` 返回新摘要；引擎 apply/change_master 仅在校验重开且 commit 成功后返回成功。backup.rs 定义 `VaultBackup::snapshot()->AppResult<BackupManifest>`、`preview(path:&Path,master:SecretBytes)->AppResult<RestorePreview>`、`restore(preview:&RestorePreview,confirmed:bool)->AppResult<()>`；恢复预览绑定文件摘要和短期事务，不长期保存主密码。

- [ ] **Step 1 — 测试：** `crash_at_each_commit_boundary_keeps_valid_file`、`external_edit_refuses_overwrite`、`disk_full_is_not_saved`、`new_master_changes_current_not_old_backup`、`restore_needs_confirmation_and_correct_master`、`snapshots_keep_latest_ten`。断言 `assert_eq!(snapshot_count,10); assert!(old_or_new_file_opens); assert_eq!(conflict,Err(AppError::Conflict));`；每个写入/同步/替换边界注入崩溃，核对之前已确认条目。
- [ ] **Step 2 — 红：** `cargo test -p shixu-native --test vault_recovery -- --ignored`；预期提交/恢复尚未实现时失败，记录 Windows 文件占用测试缺失则 BLOCKED。
- [ ] **Step 3 — 实现：** 单实例串行写，工作副本始终加密；保存后经引擎重开核对，Windows 原子替换前保留有效旧文件。恢复先验证预览未过期/摘要未变、备份当前库再替换；改主密码确认当前文件新密可开旧密拒绝后再成功返回；不自动合并外部库或导出明文。
- [ ] **Step 4 — 绿/验收：** 同命令通过，恢复记录数量与三字段值逐项一致；受限目录里无明文临时文件；一次写入失败不显示已保存。记录不能证明 SSD 物理擦除与系统历史清除的边界。
- [ ] **Step 5 — 提交：** 仅 V3 文件；`feat: add recoverable encrypted vault writes and backups`。
