# Shixu v0.1 日历与桌面整合 Implementation Plan

> 2026-10-10 用户修订：删除系统锁屏、睡眠/唤醒相关逻辑及验收；下文对应旧要求已被取代，不记为 PASS。保留手动/闲置/关窗/退出锁库、遮罩和临时秘密清理，剪贴板不自动清除。当前合同见 `docs/verification/windows-vault-lifecycle.md`。

2026-10-10 剪贴板需求修订：复制账号/密码后不因计时、锁库或退出自动清除；内容保留至用户覆盖或手动清除，可能留有密码。15 秒掩码、5 分钟闲置锁库、会话撤销和瞬时秘密内存清零保持要求；原生复制、历史/云同步排除及权限隔离仍须真实验收。
> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 把可追溯候选自动写入日历，提供安全的三字段密码界面、后台生命周期和可验证的备份恢复。

**Architecture:** EventService 独立于桌面 UI，并通过共享 SQLite 事务记录来源与撤销。主窗口与密码窗口使用不同能力集合；后台 supervisor 连接通知管道与日历，锁库仅影响密码会话。Windows 整体验收是最后门槛，不由浏览器预览替代。

**Tech Stack:** Rust、SQLite、Tauri、React、TypeScript、FullCalendar 标准功能、Vitest 与 Windows 集成测试；具体版本按已验证组合固定。

**Spec:** [已批准设计](../specs/2026-10-09-shixu-v0.1-design.md)第 3–4、9–14 节；[总览](2026-10-09-shixu-v0.1-implementation.md)的最新批准状态、类型和限制同时适用。

## Global Constraints

继承总览全局约束。自动入历无逐条确认；UnknownDate不占日期格，DateOnly不伪装全天；无拖拽改期。主密码只锁密码库，默认云端模型/登录自启关闭；锁库不暂停通知。所有写入成功必须代表持久化完成，模拟源明确标记“模拟”。

## Review Focus

继承总览统一风险；D1/D4负责旧附件与人工修改冲突，D3负责迟到秘密，D6负责备份恢复重放，D7负责真实环境与模拟证据分离。
